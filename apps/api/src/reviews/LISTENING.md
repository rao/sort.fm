# Cached listening assembly integration

Review `QueueOptions` (including `PolicyQueueOptions`), `CalibrationQueueOptions`, and `CalibrationBatchOptions` accept an optional `load(rows, {userId, now}) => Promise<CandidateAssemblySnapshot>`. It takes precedence over the legacy synchronous `assemble`. `rows` is a detached full library snapshot, including ineligible rows needed for aggregate features; eligibility filtering follows assembly.

Runtime should inject C1's `assembleLibraryCandidatesWithListeningContext` with the configured metadata training policy, the captured `now` converted to ISO, and D's owner-scoped cached `getTasteContext` reader. The loader must handle unavailable cache as truthful missing coverage and must not fetch Spotify on a queue hot path. Invalid loader results or rejected promises fail before scoring/publication. Candidate identities and coverage schema are validated by each boundary.

Each fresh candidate batch loads once. Parsed features and coverage are detached before scoring; the scorer receives cloned candidates. Coverage stays outside FeatureVector and ML request bodies, and is stored only in server-side exposure/frozen-candidate records. Adaptive policy intents also freeze coverage so recovery publishes the original snapshot. Public queue responses do not expose the coverage object. A failed adaptive selection followed by a fresh C1 fallback may load a new sample with its new eligibility snapshot. Replay of a durable selection or an existing calibration batch never invokes the loader; old frozen records remain unchanged.

`LibraryImporter` timestamps recent-listening completion after the response succeeds or fails. Spotify's current [recently played reference](https://developer.spotify.com/documentation/web-api/reference/get-recently-played) documents the `user-read-recently-played` scope, up to 50 items per request and timestamp cursors. This cache remains an incomplete recent sample. Absence of a track cannot establish zero plays. C1 owns validation, freshness and missingness semantics.

Integration dependencies: shared listening contracts (`613a47e`), C1 cached-context helper, D cache reader and frozen coverage persistence, and root runtime wiring. This API change alone does not activate listening features in a running server. No historical exposure rewrite, Spotify request, model fit or policy activation is required by this patch.

Verification covers asynchronous loading in all four queue paths, two-phase scoring without reloading, immutable features through scoring failures, durable coverage and recovery, no loading on saved batch/queue replay, loader rejection/corrupt metadata, and delayed recent-response timestamp success/failure. Actual-account aggregate audit was read-only and remains outside repository artifacts. Live backend/database verification is the integration lead's gate after D/C1/runtime are combined.
